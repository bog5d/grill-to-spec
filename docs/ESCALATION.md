# 升级 / 少问纪律（Ask-Less Escalation）

目标：默认自决、少打断；仅在真正需要拍板时升级。可核对、短文即可，勿把整份 SCP 抄进本文件。

实例参考（产品仓私有，仅写公开 owner/repo 名，不写密钥/机密）：`bog5d/cangjie-teams-channel`（仓颉 Teams Channel V1 Acceptance）。

## 四条硬规则

| # | 场景 | 动作 |
|---|------|------|
| 1 | 问题已有确定性答案 / 现有规则可覆盖 | **自决**，不要问 |
| 2 | P1 / P2 | 写下**显式假设**后继续；非终态**不得**为了「汇报」而停 |
| 3 | 不可逆操作、安全/保密、架构级未知、对外发消息、花钱 | **仅**此类升级至董事长（经总经理/司仓） |
| 4 | 名册等人设字段 | 无口述口授**不得**填写；但**不得**因此阻塞产品开发 WP |

## 自决（规则 1）

- 规则、契约、已验收 Spec、SCP、本仓库既有协议能推出答案 → 直接决定并执行。
- 重复确认「已写明的事」属于噪声，禁止。

## P1/P2 与非终态（规则 2）

- **P1**：影响方案但可用显式假设继续 → 记假设 + 继续。
- **P2**：不阻塞当前交付 → 进 Backlog / OPEN_QUESTIONS，不打断。
- 任务未到验收终态时：自动续跑；禁止停下来「先报一波」等批。

## 何时才升级（规则 3）

**只**在下列情况经总经理/司仓升级董事长：

1. **不可逆**：删除/覆写生产数据、合并到受保护分支、发布对外不可撤回变更等（按产品仓定义）。
2. **安全 / 保密**：密钥、隐私、权限边界、泄密风险。
3. **架构级未知**：会改变系统边界、数据权威源、模块契约，且现有 Spec/SCP 无法覆盖。
4. **对外发消息**：邮件、Slack、IM、工单、公开发帖等。
5. **花钱**：采购、订阅、付费 API 等。

其余一律自决或写假设继续。

## 名册字段 vs 开发 WP（规则 4）

- 名册 / roster 中的**人设、评价、口述类字段**：无当事人口述口授 → **不写**。
- 上述缺口**不得**阻塞产品开发 Work Package（实现、测试、文档、PR 等仍按 Plan 推进）。
- 缺字段记入 OPEN_QUESTIONS 或显式假设；开发路径绕开即可。

## 与 SCP 的关系

工程原则见根目录 `SCP-v3.4.md`。本文件只补「少问 / 升级」纪律；冲突时以更具体、可核对的规则为准，并在 HANDOFF 记一笔。
