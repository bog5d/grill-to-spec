# 积木化架构｜黑盒封装与验收封存（SCP v3.8 执行补充）

> 权威原则仍为 [SCP-v3.8 §6](../SCP-v3.8.md)；本文只规定如何执行，不修改 SCP 版本与正文。

**生效边界：** 本规则仅适用于本补充进入默认分支后**新开工的可复用模块（L1/L2）**；在建 WP/PR 照原门禁推进，存量可用代码不追溯重构、不强制补卡，不为封存而封存。L0 小修遵守回归与安全即可。

1. **开工先查积木：** 查成熟内部组件、相关 Skills 和既有公开接口，优先复用；新能力优先用 `Adapter/Pack/Config` 拼接，不重写稳定内核。
2. **验收才封存：** 新可复用模块必须有一张**最小模块卡**（可以写在已有 Spec/README，不另造文件）：模块名与版本、接口（输入/输出/错误）、依赖与配置、适用边界、独立 Gate 的命令/退出码/commit/Evidence、封存状态。未完成真实独立验收只标 `CANDIDATE`，**PR 合并不等于已封存**。
3. **封存后只读接口：** 新功能默认调用稳定公开接口或新增 Adapter/Pack/Config；不能为风格优化随意打开内部。确因 Bug、安全、性能、契约/依赖失效或必要扩展解封，记录理由和影响范围，**重新回归、独立验收、升版再封存**。不得硬性阻止紧急安全修复。
4. **Gate 要查，不能只喊口号：** 新 L1/L2 模块的 Reviewer 检查“复用记录、模块卡、独立验收、解封理由（若触及既封存模块）”。缺证据判 `UNKNOWN/NOT_SEALED`，不得写封存 PASS。项目/任务交付验收与模块封存是两张不同的成绩单。

**存量触发原则：** 旧模块若未来确需修改，仅对**本次修改范围**补最小接口契约和回归；不反向清洗整个仓库，不临时加门槛阻塞现有施工。生产切换、删除、架构重建继续遵守原授权与 Gate。
