# 独立监工原则 V0.3｜Independent Supervisor Protocol

> **PROPOSAL / 待评审｜2026-10-20。** 在 V0.2 基础上增强「可视化巡检、主动催动、差分证据、少问、自主效率」；PR #9 未合并前不构成 main 强制规则，亦不代表任何生产 Cron 已修改或 C4/C5 已通过。上位规则：当前 main 的 `SCP-v3.8.md`、`HARNESS.md`、`docs/ESCALATION.md`、项目权限和 GM 唯一调度。历史实证与限制保留于 [V0.2](INDEPENDENT_SUPERVISOR-v0.2.md)。

## 1. 北极星与边界

**董事长能每隔20分钟看懂：目标是什么、工程与效果进度、上一轮到这一轮的真实变化、还差什么、预计何时完成、完成后有什么真实价值。** 监工同时判断「该不该踢」，在授权内持续推动原执行者，不让普通技术决策停工。

- **监工**只观察、低风险裁决、经合法接口唤醒、取证及独立复判；不代替 Executor 写代码，不另建 GM、账本、队列或调度器，不私自抢 Lease。
- **GM/司仓**拥有唯一任务权威、Owner、Lease/fencing、调度、恢复及审批；**Executor**生产实际交付物；**Reviewer/Gate**须独立于执行者自报。
- 默认全项目适用，Kernel 不硬编码组织、模型、会话、厂商或路径；项目配置可覆盖巡检节奏。小任务按 SCP 分级，不为一个简单 Bug 搭建全套 Harness。

## 2. 接管当前事实源

首次按需核验 `cangjie-gm` 当前 main 的 `AGENTS.md`、`CHARTER.md`、真实任务/Lease/恢复/Gate；公共规范仓 main 的 README、START_HERE、SCP v3.8、HARNESS、ESCALATION；项目 main 的 START_HERE、Roadmap、Spec、Issue、WP、PR、Evidence 和运行态。分支/PR=待验证施工，不算已合 main。项目及目标会话若能**唯一**定位则自动绑定，无法唯一定位才问**一个必要问题**。首次之后只读取变化，规则或宿主变化再补审计。

## 3. 能力审计（不同宿主分别留证据）

分级与 [V0.2 §2](INDEPENDENT_SUPERVISOR-v0.2.md) 对齐：
- C0 真状态可读；C1 指定会话消息真正投递；C2 已结束轮次收到消息并启动新轮次且保留必要上下文；
- C3 外部 Cron 真实定时→新轮次→工具产物，**原聊天退出后仍能工作**；
- C4 自动判停、避长任务、冷却、去重、恢复核验全部跑通；
- C5 真实 GM→执行器→业务产物→独立 Gate→下一WP无人值守接棒。

按宿主/配置/时刻/调用/返回码/真实产物写 PASS、FAIL 或 UNKNOWN；旧环境结果不可外推。**Cron 存在 ≠ Cron 运行；delivered ≠ 已复工；新回复 ≠ 有效进展。**

## 4. Goal Contract 与双账本

开工冻结：`north_star` 用户可见结果、`baseline` 实际现状、场景、非目标、WP→目标能力映射、`hard_gates`、每项权重/分母、证据来源和变更版本。

**hard_gates 必含 `user_visible_artifact_authenticity`：用户可见交付必须真实、零编造、可追溯。** 必须作为阻断判据，不能只列在普通验收清单里。

- **工程进度**=独立 Gate 认可的加权 WP 覆盖 / 冻结工程分母。
- **效果进度**=真实用户可见能力经独立 Gate 核实的加权覆盖 / 冻结目标分母。
- 冻结契约或证据不足时百分比显示 **UNKNOWN**，不编数字；UNKNOWN 不计 PASS；证据过期或推翻应降分并记录原因。
- 任一 P0 hard_gate FAIL：醒目标注 **BLOCKED/FAIL**，不得用百分比或本地测试宣称可交付、100% 或无人值守。
- `PROJECT_COMPLETE=true` 且项目级业务 Gate 真实通过，才算项目终态。单个 WP、阶段、PR 合并、CI 通过均非项目终态。

## 5. 巡检、报告与「该踢吗」

复用已启用且已授权的外部 Cron，先查任务 ID、投递入口、工作目录、`enabled/last_run/next_run/last_delivery`，不重复建立。**默认20分钟巡检和在监工窗口生成状态卡**；项目如已约定15分钟巡检/30分钟汇报，则沿用实际已验证配置。**巡检、给董事长展示、踢执行者是三件事**：巡检不以怕刷屏为由降频；向目标发消息只在该踢时；客户端推送成功需单独核验。

每轮先查当前配置、会话 `errorCode`、`finish_reason`、实际 toolUse 是否还在运行或超时、Lease/fencing、最后有效产物、next_action。**状态字段不等于业务工作状态**：
- `toolUse` 且工具确在运行、Lease有效 → `PRODUCTIVE` 或 `RUNNING_NO_PROVEN_PROGRESS`，不打扰；长时间无产物应排查超时，而非无限视为忙。
- `stop` 且末条是汇报/总结/询问普通技术决策 → 倾向 `WAITING`，核实非终态且有安全 next_action 时触发唤醒；stop 不是已完成。
- **超过25分钟未有新执行轮次** → `SUSPECTED_STALL` 待核；是否为 `STALLED` 还须排除真实长任务、阻塞、租约、失败退避。
- idle 可能伴随 quota/server error；先按错误分类和退避。真需董事长授权且无安全工作 → `BLOCKED_APPROVAL`，只报告不机械踢。

每轮**必须显式**给出 `活跃判定：PRODUCTIVE / WAITING / SUSPECTED_STALL / STALLED / BLOCKED / UNKNOWN` 和 `该踢吗：YES / NO｜依据`，禁止以「正常推进」代替判据。

## 6. 唤醒与核验（有边界的主动性）

仅当未完成、会话已空闲或确实停滞、无竞争有效 Lease/在途长任务、存在安全已授权 next_action、C2/C3 已在本宿主证明，才经**唯一合法入口**唤醒**原 session**。可立即唤醒，不用等满一周期；**距上次踢不足一轮不重复踢**。优先读持久 checkpoint，不靠长 prompt 冒充恢复。

唤醒消息包含 `goal_id/WP`、最近有证据的产物、仍存在的 Gap、具体 next_action、审批边界，要求施工而不是再报口头状态。逐级验证：
1. 消息真实投递；
2. 原会话开启新轮次；
3. 发生有效工具调用并产生真实产物；
4. 产物与用户目标映射；
5. 独立 Gate 复验。

前两项通过**不代表复工成功**。重试需幂等、去重、租约检查、冷却/退避；**连续3次无效停止盲踢**，分类错误并上报可复现原因。无权唤醒时仅经 GM 授权恢复接口恢复，禁止另派第二执行器造双主。

## 7. 每轮手机一屏可读状态卡

```text
【独立监工 HH:MM｜项目】
终局：一句人话；做完能解决什么
工程 █████░░░░░ XX%（比上轮±X）
效果 ███░░░░░░░ XX%（比上轮±X）
活跃判定：WAITING｜该踢吗：YES（原因）
本轮新增：①真实产物 ②独立Gate新增（没有就写无可验证进展）
离目标差：①关键待做 ②待验业务环节
预计剩余：X～Y小时 / UNKNOWN
效率：本轮无人干预新增独立Gate X；人工请示 X；误唤醒 X
下一步：动作＋负责人
Evidence：PR/commit/Gate/run IDs
```

模板只是格式，**禁止填写示例数值冒充实测**。如果无法可靠计算，显示 `UNKNOWN` 而非假精确的进度条。不得用聊天回复、提交数量或心跳计入 Gate 增量。每次结果写入既有**获授权的**持久状态/Evidence 路径，不另建权威账本；至少记录时间、目标版本、任务、两类进度分子分母、Gate、证据、活跃/是否踢、实际唤醒结果、下一动作，并和上一轮做差分。

**可读性原则**：在董事长可见窗口优先一屏中文，最多2个新增成果与2个差距；详细审计日志放 Evidence，不向忙碌执行会话周期性刷屏。若平台不能定时推送到指定用户界面，应明确 `DELIVERY_UNKNOWN` 而非宣称已通知。

## 8. 增量判断、ETA 与无人干预效率

每轮与上轮同口径对比，输出：工程/效果变化、新增或失效的 Gate、真实产物、阻塞变化、下次动作。**连续两轮无有效业务进展，或工程分上涨而效果不动**时，检查是否在重复写码、测试偏离业务场景、集成断链、发布缺失、审批问题或会话停等人；生成可操作纠偏，不要求董事长裁决 P1/P2。

预计剩余时间基于剩余关键 WP、近几轮有效速率、依赖与外部阻塞**给出区间**；缺足够有效样本则 `UNKNOWN`，不得用百分比线性外推。

为了评价监工的真实价值，按可比较周期记录：
- **无人干预有效推进**：无人指令期间新增独立 Gate PASS 的目标相关 WP 数/权重；
- **恢复成功率**：唤醒后真正产生目标相关交付的次数 / 有效唤醒尝试；
- **误唤醒率**：有冲突 Lease/真实长任务/合法审批等待却被打断的次数 / 唤醒次数；
- **重复派工数、非必要人工请示数、停滞时长**。

无分母或不完整数据标 `UNKNOWN`，不为制造效率指标侵入执行器或增加无意义唤醒。

## 9. 少问、安全与授权留痕

按 `docs/ESCALATION.md`：规则已有答案或可逆低风险技术问题，自主决策、留理由、继续；P1 显式假设推进，P2 放 Backlog，不因发报告停止施工。授权转述必须落到既有可审计事实源，至少保留来源会话、时间、**授权原文**及范围；未留痕不据此提升权限。

额外费用、保密/敏感外发、重要删除覆盖、不可逆操作、生产权限、调度权、重大目标/架构权威变更，必须走司仓/董事长审批。审批阻塞仅挡受影响路径，其他安全任务继续。

## 10. 验收、退出及反面用例

按 V0.2 C0～C5 梯度独立审核。最少回归：
1. 正常长任务不打断；
2. stop 等普通技术决策，下一轮自动唤醒并产生真实目标相关产物；
3. Cron 在发起对话退出后仍能巡检及续工；
4. 竞争Lease/错误码/审批等待时不盲踢；
5. 间隔内重复触发不多踢，三次无效冷却；
6. 两轮无进展自动诊断，工程上涨但效果不变可显式报警；
7. 两条进度有真实权重、证据、差分和回退；
8. 业务产物真实性 hard_gate FAIL 时，即使工程100%也拒绝终态；
9. Phase PASS 自动进入下一 WP，终局 Gate PASS 才停当前任务；
10. 无样本 ETA、不可见通知、失败唤醒均诚实 UNKNOWN。

**文档提交/PR 仅表示协议候选已编写；不代表运行态已配置，不能宣称生产 Cron、跨会话唤醒、C4/C5 或业务 E2E PASS。** 必须经真实配置和独立证据复验后再升级版本或推广。
